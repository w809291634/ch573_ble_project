# 模块功能与接口说明 — apl_inputex（通用输入）

> 文档版本：v0.2.8　对应代码：当前目录（`apl_input.c` / `apl_input.h`）
> 框架入口：[../../../README.md](../../../README.md)

## 1. 功能与限制

### 用途 / 特性
- **是什么**：一套与业务无关的通用按键/开关输入识别模块。上层注入"扫描、读电平、毫秒时基、事件回调"，模块内部完成激活记录、去抖、分级长按超时、组合按识别与统一事件上报。
- **统一事件**：单键与组合键统一经一个回调上报（`input_event_cb_t`），应用只需实现一个 `app_input_event()`。
- **单/组双模式**：通过 `BOARD_CONFIG_EN_INPUT_MASK` 切换——
  - `MASK==1` 组模式：多键同时达到本级超时判定为组合按下/抬起（`INPUT_EV_COMBO_DOWN/UP`）；
  - `MASK==0` 单键模式：逐对象上报单键事件（`INPUT_EV_SINGLE_DOWN/UP`）。
- **表驱动超时**：`input_timout_t.timeout[]` 下标即超时级（T0=去抖/确认、T1=长按、T2=超长按…），可配置 1..N 级，值 `0` 表示该级无效。

### 适用范围
- 需要"短按/长按/超长按/组合动作区分"的按键输入场景（设备面板、遥控器、组合键手势等）。
- 单线程轮询场景：主循环周期调用 `Input_Scan()`（如 5ms 周期）。

### 不适用范围
- 多任务/中断并发读写同一输入状态（模块内部为进程级静态变量，未做临界区保护；并发场景需外部串行化或将状态迁移到独立任务）。
- 需要硬件去抖、需要极低时延硬实时输出的场景（本模块为软件去抖轮询模型，事件有 ≤ 一个扫描周期延迟）。
- 超过 `BOARD_CONFIG_INPUT_OBJS_NUM` 的对象数量（多余对象被钳制丢弃）。

### 技术指标（可复现：`test/host_unit_test` 双变体，gcc -Os）
| 指标 | 组模式 MASK=1 | 单键模式 MASK=0 |
| ---- | ---- | ---- |
| 代码尺寸 text（apl_input + bits_ops） | ≈ 2.1 KB | ≈ 1.3 KB |
| RAM bss（含对象数组与管理器，data=0） | 192 B | 160 B |
| 栈开销 / 帧 | 常量级（无递归、无大临时结构，仅标量与循环变量） |
| 时间复杂度 / 帧 | O(Objs × ToutEvtNum)，5ms 周期下 CPU 占用可忽略 |
| 扫描吞吐 | 30 万+ 次扫描（soak + 随机干扰）双变体一起约 1 秒跑完 |
| 稳定性 | 确定性 30 万次扫描 + 5 万步随机干扰 soak（`test_soak_symmetry`/`test_soak_random`） | 按下/抬起对称、无崩溃、压力后可恢复 |

> 注：上表为主机 gcc -Os 实测；执行 `& .\test\host_unit_test\run.ps1` 会自动编译测量对象并在系统提供 `size` 时输出 text/data/bss。目标板 ROM/RAM 请以工程构建 `size`/`MAP` 为准。

### 兼容性（跨平台 / 跨工具链）
- **目标平台**：ESP32-S3（ESP-IDF v5.3.1，`test/ESP32s3_apl_inputex_test`）；STM32F103（Cortex-M3，`test/STM32F103_apl_inputex_test`，MDK/ARM Compiler）。
- **编译器/工具链**：host 已验证 MinGW gcc 13.1（C11）；STM32 工程用 Keil MDK（ARMCC/AC6）编译并链接通过（ARMCLANG AC6, Cortex-M3，产物见 `test/STM32F103_apl_inputex_test/Objects/`）。
- **可移植性**：`common/` 不包含任何厂商头文件；GPIO / 毫秒时基 / 打印通过工程层回调或宏注入，平台差异全部收敛在 `board/`、`app/`（含 `main/`）层。

### 已知限制
- 单一实例：模块内部 `g_in_mgr` / `g_in_objs` 为静态全局，同一时间仅支持一个输入管理器。
- 组合抬起的识别以"全部成员松开"为准（见 `apl_combo_notify` 的 `inact_mask` 判定）。
- 去抖窗口由 `timeout[0]` 决定；按压时长 < `timeout[0]` 不产生事件。

## 2. API 说明

### 头文件
```c
#include "apl_input.h"   // 前提：已定义 board_config.h 中的 BOARD_CONFIG_* 宏
```

### 2.1 初始化（统一事件）
```c
int Input_Mgr_InitEvent(const input_mgr_cfg_t* cfg);
```
| 项 | 说明 |
| -- | ---- |
| 原型 | `int Input_Mgr_InitEvent(const input_mgr_cfg_t* cfg);` |
| 参数 | `cfg`：统一配置结构体（见下表），不可为空 |
| 返回值 | `APL_INPUT_OK=0` 成功；负值见"错误码"表（统一可追溯） |
| 前置条件 | 已定义 `BOARD_CONFIG_INPUT_OBJS_NUM / BOARD_CONFIG_INPUT_TOUT_EVT_NUM / BOARD_CONFIG_EN_INPUT_MASK`；`cfg->read`、`cfg->get_ms`、`cfg->event_cb` 已就绪 |
| 上下文 | 任何线程（内部整体清零）；重复调用可复位状态 |
| 注意 | `obj_num` 超过容量会被钳制到 `BOARD_CONFIG_INPUT_OBJS_NUM`，不会越界写 |

**错误码（`Input_Mgr_InitEvent` 返回）**：

| 宏 | 值 | 含义 |
| -- | -- | ---- |
| `APL_INPUT_OK` | 0 | 成功 |
| `APL_INPUT_ERR_PARAM` | -1 | `cfg` 为空指针 |
| `APL_INPUT_ERR_EVT_CB` | -2 | 事件回调 `event_cb` 缺失 |
| `APL_INPUT_ERR_READ` | -3 | 读电平回调 `read` 缺失 |
| `APL_INPUT_ERR_TIMEBASE` | -4 | 毫秒时基 `get_ms` 缺失 |

> 返回类型恒为 `int`，应用按 `!=0` 即判失败；`test/host_unit_test` 已用 `test_init_invalid_args` 锁定上述契约。

**分级日志**：默认关闭；在 `board_config.h` 中把 `APL_INPUT_LOG_E`/`APL_INPUT_LOG_I` 映射到工程日志（如 `log_e`/`log_i`）即可开启模块日志（init 失败、`Input_Scan` 未初始化等关键状态）。模块实现会在自身编译单元包含 `debug_log.h`，因此该映射在 ESP-IDF、MDK 与主机工程中均可直接生效。

`input_mgr_cfg_t` 字段：
| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `get_ms` | `get_ms_cb_t` | 是 | 毫秒时基，返回当前 ms |
| `event_cb` | `input_event_cb_t` | 是 | 统一事件回调（单键+组合均在此） |
| `read` | `read_level` | 是 | 单路读电平回调：`read(i)` 返回 1=激活 |
| `scan` | `gp_ins_scan_cb_t` | 否 | 键值扫描钩子（如批量读 GPIO） |
| `timout` | `const input_timout_t*` | 否 | 激活超时时间表；`NULL` 则所有级为 0（不触发） |
| `obj_num` | `uint32_t` | 否 | 对象数量，`0` 用 `BOARD_CONFIG_INPUT_OBJS_NUM` |
| `event_user` | `void*` | 否 | 透传用户数据 |

### 2.2 周期扫描
```c
void Input_Scan(void);
```
| 项 | 说明 |
| -- | ---- |
| 上下文 | 单线程轮询上下文（主循环/任务），周期调用 |
| 行为 | 读全部输入 → 更新激活/超时状态 →（组模式）统一组事件回调 |
| 注意 | 未初始化或 `read==NULL` 时安全返回；不要在回调内再次重入 `Input_Scan` |

### 2.3 事件结构
```c
typedef struct { input_evt_t evt; uint32_t level, idx, mask, active_ms, elapsed_ms; } input_ev_t;
```
| 事件 | 含义 |
| ---- | ---- |
| `INPUT_EV_SINGLE_DOWN` | 单键激活且达到本级超时（`idx`=键位，`mask=1<<idx`） |
| `INPUT_EV_SINGLE_UP` | 单键释放（`idx`=键位） |
| `INPUT_EV_COMBO_DOWN` | 多键同时达到本级超时（`mask`=组合掩码） |
| `INPUT_EV_COMBO_UP` | 组合全部释放（`mask`=组合掩码） |

字段：`level`＝超时级（0..TOUT_EVT_NUM-1）；`active_ms`＝本次激活起始时刻；`elapsed_ms`＝距激活时长（按下＝hold，释放＝持续时长）。

### 2.4 保持掩码复位（组模式）
```c
static inline void Input_Mgr_ClearToutBk(input_mgr_t* in_gp);   // 仅 MASK==1 编译
```
模块在完成组合抬起通知后会自动复位所有超时级"保持掩码"，避免下一周期组单击失效。
该内联函数仅供需要主动取消当前组合周期的集成方使用。

### 设计要点 / 注意事项
- 事件回调用**独立 `if`** 判断组合掩码，避免 `else-if` 造成掩码重叠时漏触发。
- 组合抬起以 `inact_mask` 记录"全部松开"再上报；单键释放时若仍有 `maskbk` 保持则视为组合未完全松开。
- 调试/用日志：参考 `.app/` 中的 `INPUT_DBG` / `GP_DBG0` / `GP_DBGX` 分级打印约定。

## 3. 配置项说明

以下宏在工程 `board/board_config.h` 中定义，供 `apl_input.h/c` 使用：

| 配置宏 | 类型 | 范围 | 缺省建议 | 含义 | 约束 / 非法配置行为 |
| ------ | ---- | ---- | ------ | ---- | ------------------- |
| `BOARD_CONFIG_INPUT_OBJS_NUM` | 无符号整型 | 1..31 | 按键路数 | 输入对象容量 | 非法值在编译期报错；`obj_num` 超过容量仍会在初始化时钳制 |
| `BOARD_CONFIG_INPUT_TOUT_EVT_NUM` | 无符号整型 | 1..12 | 3（T0/T1/T2） | 超时级数 | 非法值在编译期报错；保证内部状态位不重叠 |
| `BOARD_CONFIG_EN_INPUT_MASK` | 0/1 | {0,1} | 1（组模式） | 单键(0) / 组(1) 模式 | 非 `0/1` 在编译期报错 |

| `timeout[0..N-1]` | 无符号整数 ms | ≥0 | T0=25,T1=1000,T2=5000 | 各级超时 | `0` 表示该级禁用；非递增也会被逐级判定（未触达本级则 break） |

> 时基与电平回调通过 `input_mgr_cfg_t` 运行时注入（函数指针），不占用宏配置。
